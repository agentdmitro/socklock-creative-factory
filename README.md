# SockLock Creative Variant Factory (MVP)

Local-first tool that turns one source MP4 into three distinct 10-second vertical ad variations
(720×1280, H.264), lets a person review and **accept** them, and measures what that cost in human time.
Everything runs on your machine: no accounts, no external analytics, no external video services.
AI ideation is optional (Mock mode by default).

Flow: **Source → Concepts → Review**. Step 1: upload the video, paste script/product/CTA, choose 3, 6 (default) or 9 concepts.
Step 2: every concept (angle, hook, opening line, on-screen text, CTA, rationale) is a plain editable form with one
"Make a video" switch (the first 3 start on, up to 5 allowed); create the videos from there. Step 3: preview,
accept/reject (with an optional reason), finish to a summary page with the approved videos to download.
Idea time is tracked apart from video time. The hook and the opening line (as a subtitle under it) show for 2 s, then the on-screen text over the demo, then the CTA. Insights is one click away in the header.

> **Business targets are targets, not results.** Baseline 180 designer-minutes per accepted variation;
> initial target ≤ 86 (≈52% lower), stretch ≤ 58 (≈68% lower). Nothing in this repo claims they were achieved.
> The tool only reports what it measured, and labels every forecast as a forecast.

## Prerequisites

- Node.js 20.9+ (tested on 22)
- FFmpeg and ffprobe on your `PATH` (with `libx264`): macOS `brew install ffmpeg`, Debian/Ubuntu `sudo apt install ffmpeg`,
  or set `FFMPEG_PATH` / `FFPROBE_PATH`
- A bold sans-serif system font (found automatically; override with `FONT_PATH`)

The app checks these on load and shows a notice with a "Check again" button if something is missing.

## Reproducible demo (no third-party media)

```bash
npm run demo:media           # writes demo/sample-source.mp4: synthetic gradient + test card, generated by FFmpeg
npm run dev                  # terminal 1
npm run demo                 # terminal 2: scripted end-to-end run + telemetry assertions (uses Mock ideas, never a paid API)
```

`npm run demo` does upload → generate → edit → render (plus one deliberately invalid render) → ranged preview request →
accept/reject → export → reads Insights, checks every output with ffprobe and a full decode, and asserts that the recorded
telemetry equals the actions it took. It is tagged **scripted**: it appears under Insights → "Scripted demo runs" and never
counts toward human time. To produce *human* measurements, use the UI with `demo/sample-source.mp4` (or your own footage).
Walkthrough for a recording: [docs/DEMO.md](docs/DEMO.md).

Verify a downloaded file yourself:

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,pix_fmt:format=duration -of compact socklock-variant-statement.mp4
ffmpeg -v error -i socklock-variant-statement.mp4 -f null -    # no output = decodes cleanly
```

## How a variation is built

| Time   | Content |
| ------ | ------- |
| 0–2 s  | Hook text on a template-specific background (some use a still from your segment) |
| 2–8 s  | Your chosen 3–12 s segment, retimed to exactly 6 s, muted, with a caption |
| 8–10 s | Brand and CTA button |

Default framing is **Fit** (whole frame visible); **Fill** crops. Original audio is dropped; a silent AAC track is added for
placement compatibility. Text is drawn with `@napi-rs/canvas` and composited by FFmpeg (many FFmpeg builds lack `drawtext`).

## Review, accept, export

- The preview player shows the Hook / Demo / CTA parts on the timeline; Space plays/pauses and ← → seek when the video is focused.
- **Accept** and **Reject** are explicit. Only accepted videos can be downloaded.
- Editing the copy, segment or framing after a render marks the video *Outdated* and withdraws its decision. "Re-render N changed videos" re-renders only those.
- "Finish session" closes the session (and warns if videos are undecided).

## Insights (measured) and scenarios (forecast)

Open **Insights** in the header (`#insights`). Two clearly separated tabs:

**Measured** — accepted variations, human time per accepted variation, first-pass acceptance, rendering time and failure rate,
AI/API cost (estimate), hands-on vs waiting time, an activity funnel, and two CSV downloads (sessions, raw events).
A *Show* selector separates hands-on sessions (default), scripted demo runs, and all data.

Definitions:
- **Accepted** = explicit Accept on a successfully rendered video that has not been edited or re-rendered since. Generating ideas never counts.
- **Hands-on time** = gaps between real interactions (pointer, keys, typing, video playback), each capped at 15 s so being away is not counted.
  The clock stops during upload, AI and rendering (tracked as *waiting*) and while Insights is open.
- **Human time per accepted** = hands-on minutes of timed sessions ÷ accepted variations in those sessions (time on rejected videos is included).
  Scripted runs have no human timing and are excluded.
- **First-pass acceptance** = accepted on the first render ÷ decided (accepted + rejected). Any re-render removes first-pass status.
- **Rendering** = server-measured duration of successful renders; **failure rate** = failed ÷ attempted renders (including invalid requests).
- **Export** = a download the server actually served in full (previews use range requests and never count).
- **AI cost** = reported tokens × list prices (`AI_PRICE_*`). It is an estimate, not a billed amount. Mock mode is free.

**Business scenarios** — a forecast, styled and labelled differently from measurements. Inputs: baseline and improved minutes per accepted
variation (conservative 120 / base 86 / optimistic 58 as editable placeholders), monthly production hours, review minutes, AI cost, USD→EGP rate,
other running costs, onboarding (hours, hourly cost, amortisation), media spend per extra variation, and marginal ROMI per scenario.
Output: capacity, extra variations, incremental spend, return, itemised costs, **net incremental EGP** and **break-even ROMI**
(the formulas are on the page and in `src/lib/scenarios.ts`). All defaults are illustrative; a negative result is shown as negative.
"Use my measured value" appears only when there are at least 3 accepted variations in timed sessions with a plausible time (≥ 1 min), or a non-zero real AI cost.

## Architecture (short)

```
Browser (Next.js client UI)                         Server (Next.js route handlers, Node runtime)
  Factory ── steps: Source / Variations / Review      /api/source    upload → ffprobe validate → job dir in OS temp
  SessionTracker (src/lib/telemetry.ts)               /api/concepts  Mock or Gemini ideation (validated, cached, no retries)
    hands-on vs waiting clock, edit bursts            /api/render    FFmpeg + canvas cards → verified MP4 (one per request)
    POST /api/events  (human actions only)            /api/jobs/…    range-capable video serving; downloads are logged as exports
  Insights + ScenarioCalculator                       /api/events    whitelist-validated client events
    GET /api/insights, /api/insights/export           data/events.jsonl   append-only event log (the only persistence)
```

- **Storage**: one append-only JSON-lines file, `data/events.jsonl` (override with `CVF_DATA_DIR`). Single user, inspectable, copyable, a torn write
  damages at most one line (readers skip it). It holds ids, counts, durations, token counts and costs only: never script text, copy, file names or prompts.
- **Who records what**: the server records what it observes (upload, AI generation, render success/failure and duration, exports); the browser reports
  human actions (edit, accept, reject, session start/finish, cumulative time). One server clock stamps everything.
- **Pure modules** `src/lib/analytics.ts` (replay + aggregation + CSV) and `src/lib/scenarios.ts` are dependency-free and unit tested.
- **UI**: custom components with CSS-variable tokens in `src/app/globals.scss` and compile-time tokens in `src/styles/_tokens.scss`.

## Idea providers (optional AI)

Works fully offline in **Mock mode** (deterministic, free, labelled in the header). To use Gemini:

```bash
cp .env.example .env.local   # set GEMINI_API_KEY (server-only, git-ignored); AI_PROVIDER=gemini to default to it
npm run ai:check             # confirms GEMINI_MODEL exists for your key (metadata call, no tokens)
```

- Model: `gemini-3.1-flash-lite` by default (override with `GEMINI_MODEL`; set `AI_PRICE_*` to match).
- One batch request returns three angles (Pain-first, Product-demo-first, Benefit-first), each with hook,
  supporting text, CTA and a short explanation. The SDK's default retries are disabled; output tokens are capped.
- Responses are schema-constrained, then validated at runtime. Offers, discounts, guarantees, superlatives,
  certification claims and numbers that are not in your product context/script are rejected per concept and
  replaced with Mock copy. Quota, timeout, auth or invalid-JSON failures fall back to Mock with a visible notice.
- Only the click on "Continue to variations" (or "Regenerate with AI") can call the API. Unchanged inputs reuse
  the current concepts; identical requests are cached for 15 min and concurrent ones share one call. Rendering never calls AI.
- Shown: provider, model, time, tokens, and an **estimated** cost from list prices. The billed amount is not
  returned by the API; see your Google billing console. Metadata (never prompts or copy) goes to the server log
  and `.tmp/ai-usage.jsonl`.
- Privacy: in Gemini mode the script and product text are sent to Google. The video never is.

## Limits and safety

- Upload: MP4 only, up to 200 MB, streamed to disk with a hard byte cap. The `ftyp` header and
  real media properties (ffprobe) are checked: 3 s to 30 min, short side at least 240 px.
- Jobs live in the OS temp directory under `socklock-creative-factory/<uuid>`; ids and output
  names are validated, expired jobs (2 h) are swept on the next upload, and render scratch files are
  removed after every render.
- FFmpeg/ffprobe are run with argument arrays, never through a shell.

## MVP limitations

- Single user, single machine; no authentication, sync or multi-user aggregation. Data is a plain file with no rotation.
- Hands-on time is inferred from interaction events with a 15 s idle cap. It is an estimate: reading or thinking without touching the keyboard or mouse is missed (or capped), and playback counts as activity.
- It measures in-tool time only. Briefing, stakeholder review and offline work are not captured, so it is **not** a like-for-like proof of the 180-minute baseline.
- Analytics events are best effort (fire-and-forget). A failed request leaves a gap; closing the tab sends a final time snapshot via `sendBeacon` where the browser allows it.
- Acceptance is a personal judgment; there is no second reviewer, A/B result or in-market performance data. ROMI and spend in the calculator are assumptions, not outcomes.
- Cost is estimated from list prices; the billed amount comes from your Google console. Mock mode is deterministic and not a quality benchmark.
- Jobs and rendered files live in the OS temp directory and expire after 2 h; export before finishing.
- One template family, 9:16 only, no music, no brand-asset library, no batch queue.
